## 3. AI 응답 품질 평가 (3차 계승)

챗봇 코어(LangGraph 에이전트, GraphDB/VectorDB 검색)는 4차에서 로직 변경이 없어, 3차
평가 결과를 그대로 유지한다. 전체 원본은
[`SKN31-3rd-1Team/산출물/성능평가.md`](../SKN31-3rd-1Team/산출물/성능평가.md).

| 평가 대상 | 지표 | 결과 |
|---|---|---|
| GraphDB tool 라우팅 | Precision / Recall (10개 질의 세트) | 1.0000 / 1.0000 |
| VectorDB 검색 | Hit Rate / MRR (10개 질의 세트) | 1.0000 / 0.9333 |
| 응답 정량 평가 (RAGAS, 15개 테스트셋) | Faithfulness / Answer Relevancy / Context Precision / Context Recall | 0.2657 / 0.4088 / 0.4500 / 0.6000 |
| 응답 정성 평가 (실배포 환경 2건) | 정확성·유용성·톤·일관성 | RAGAS 점수는 낮았지만 실제 답변은 근거 인용·공감 표현이 적절해 정성 평가는 양호 — 정량·정성 지표가 어긋난 사례로 3차 문서에 기록됨 |

> RAGAS 점수가 낮게 나온 원인은 3차 문서에서도 "실제 서비스 상황과 다른 조건에서
> 평가"로 짚어뒀다. 4차에서 별도 재평가는 진행하지 않았다 — 챗봇 로직이 그대로라
> 재평가해도 같은 경향이 예상되며, 필요 시 7절의 향후 과제로 남긴다.

## 6. 결론

이번 4차 개발분(치매 센터 찾기, 오늘의 대화)에서 발견된 결함 10건 중 8건은 코드
수정으로, 2건은 배포 설정(카카오 콘솔·Vercel 환경변수) 정정으로 해결했다. 3차에서
검증된 챗봇 핵심 로직(GraphDB/VectorDB/에이전트)은 변경 사항이 없어 재평가하지 않았고,
기존 성능 지표를 그대로 인용했다. 오늘의 대화 기능은 프론트엔드 구현·검증이 끝난
상태로 백엔드 병합을 기다리고 있다.

## 7. 향후 과제

- 자동화 테스트 도입: 프론트엔드는 컴포넌트 단위 테스트(예: Vitest + Testing Library),
  백엔드는 엔드포인트 단위 테스트(pytest + FastAPI TestClient) 구축
- 오늘의 대화 백엔드 병합 후 종단 간(E2E) 테스트 수행 (TC-05-08)
- RAGAS 재평가: 4차에서 사용자 흐름이 늘어난 만큼, 실사용 로그 기반 질의로 재평가 검토
- Vercel 프리뷰 도메인 CORS 허용 여부 검토
