# 요구사항 정의서

> 치매정보알리미(4차 단위 프로젝트) 기능 및 비기능 요구사항을 정의한다. 실제 구현된 코드
> (`dementia_front`, `SKN31-4th-1Team`)를 근거로 작성했으며, "구현 상태" 컬럼으로
> 완료/진행 중을 구분한다.

---

## 2. 비기능 요구사항

### NFR-01. 보안 — 4차 착수 초기(8/2) 우선 처리

> 3차 회고에서 "민감한 개인정보에 대해 보안 측면의 아쉬움"이 직접 언급되어(3차
> README 7절), 4차는 신규 기능보다 인증 방식 재구축을 먼저 진행했다. 상담·게임·
> 체크인 등 회원 데이터를 다루는 기능이 늘어나는 시점이라 우선순위를 앞당겼다.

| ID | 요구사항 | 근거 |
|---|---|---|
| NFR-01-01 | JWT 로컬 검증 | Supabase Auth 서버 왕복 없이 ES256(JWKS)/HS256 로컬 서명 검증. `alg` 화이트리스트로 `none` 알고리즘 공격 방어 (`server/auth.py`) |
| NFR-01-02 | RLS(Row Level Security) | `game_scores`, `subjects`, `state`, `contexts` 등 사용자 데이터는 `auth.uid() = user_id` 정책으로 본인 것만 접근 |
| NFR-01-03 | service_role 키 격리 | service_role 키는 서버(`main.py`의 회원탈퇴 등)에서만 사용, 프론트엔드는 anon/publishable 키만 사용 |
| NFR-01-04 | 에러 메시지 비노출 | 내부 예외(`str(e)`)를 사용자 응답에 그대로 노출하지 않음 |
| NFR-01-05 | API 키 도메인 제한 | Kakao Map JavaScript 키는 콘솔에 배포 도메인을 등록해 타 사이트 도용 방지 (REST API 키는 프론트에 사용하지 않음) |

### NFR-02. 성능 / 가용성

| ID | 요구사항 | 근거 |
|---|---|---|
| NFR-02-01 | 지도 데이터 정적 서빙 | 센터 313곳 데이터를 정적 JSON(`public/data/centers.json`)으로 번들, Render 백엔드 콜드스타트(30초+)의 영향을 받지 않음 |
| NFR-02-02 | 카카오 API 쿼터 절감 | 지도 표시·클러스터링·길찾기는 쿼터 미소모. 주소→좌표 변환(Geocoder)만 호출당 1건 소모 |
| NFR-02-03 | 백엔드 웜업 | `/keepalive` 엔드포인트로 Neo4j/Qdrant 연결을 주기적으로 활성화 |
| NFR-02-04 | 마커 렌더링 최적화 | 지도 마커를 id 기준 캐싱, 필터 변경 시 재생성 대신 `setMap` 토글 |

### NFR-03. 접근성 (장·노년층 대상)

| ID | 요구사항 |
|---|---|
| NFR-03-01 | 본문 최소 `text-base`(16px), 클릭 대상 최소 44×44px |
| NFR-03-02 | 색만으로 정보를 전달하지 않음(tone 등은 색+텍스트 라벨 병행) |
| NFR-03-03 | 키보드만으로 검색→결과 선택까지 가능 |
| NFR-03-04 | 명도 대비 4.5:1 이상 |

### NFR-04. 데이터 정합성

| ID | 요구사항 |
|---|---|
| NFR-04-01 | 날짜 처리는 KST 로컬 기준으로 명시 계산(UTC 자동 변환 의존 금지) — `game_scores.play_date`에서 이미 2회 발생한 버그 클래스 재발 방지 |
| NFR-04-02 | 좌표(위도/경도)는 반올림·정수화 없이 float 원본 보존 |
| NFR-04-03 | 위치 정보(검색 좌표 등)는 서버/DB에 저장하지 않고 브라우저 메모리에만 보관 |

### NFR-05. 서비스 원칙 (진단 금지)

| ID | 요구사항 |
|---|---|
| NFR-05-01 | 챗봇·데일리체크인·게임 통계 모두 "진단하지 않고 안내만 한다"는 원칙을 따른다 — 병명 단정, 인지 점수·등급 산출, 시계열 해석 문장 생성을 금지한다 |

## 3. 범위 밖 (이번 4차에서 다루지 않음)

- 데일리 체크인 이력·추이 조회(`GET /api/checkin/history`) — 향후 확장 항목으로 남김
- 게임 리더보드/랭킹 — 장·노년층 자기관리 앱 특성상 의도적으로 배제
- 상담 챗봇의 신규 LLM 코어 변경 — 3차 에이전트 로직을 그대로 계승
